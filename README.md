# Prism — 웹

**흩어진 프롬프트를 한 갈래로.**

팀이 잘 통한 프롬프트를 각자 메모장에 두지 않고 한곳에 모아 두는 사내 위키.
이 저장소는 그 **화면**이다. API 는 [prism-server](https://github.com/SoundmindWiki/prism-server) 에 있다.

- Nuxt 4 (SPA, `ssr: false`) · Tailwind CSS 4 · TypeScript
- 빌드 결과가 순수 정적 파일이라 서버에 Node 가 필요 없다


## 이름과 로고

프리즘을 지난 빛이 여러 갈래로 갈라지듯, 흩어져 있던 프롬프트가 한곳을 지나
정돈되어 나온다는 뜻이다. 로고는 삼각형 프리즘과 갈라져 나오는 세 갈래 빛이고,
16px 파비콘에서도 뭉개지지 않도록 삼각형은 선이 아니라 면으로 그렸다.

- 마크: `web/public/favicon.svg`
- 화면용 컴포넌트: `web/app/components/AppLogo.vue` (로고), `AppWordmark.vue` (로고 + 이름)
- 브랜드 색: 인디고 `#4F46E5`, 빛 세 갈래는 앰버 `#FBBF24` · 에메랄드 `#34D399` · 스카이 `#38BDF8`

이름을 바꾸려면 위 두 컴포넌트와 `favicon.svg`, `nuxt.config.ts` 의 `title`·`titleTemplate`,
그리고 `config/database.yml` 의 DB 이름을 함께 고치면 된다.

왼쪽 사이드바에 도메인 트리와 카테고리 트리가 늘 떠 있고, 문서를 열면 오른쪽에 "누가 언제 무엇을" 이 붙는다.

## 무엇이 되는가

### 위키 (로그인한 구성원 누구나)

- 문서 등록 / 수정 / 보관
- 제목·본문·태그를 한 번에 훑는 검색, 카테고리·도메인·태그 필터, 4가지 정렬
- **변수 채워서 복사** — 본문의 `{{고객사명}}` 같은 자리표시자를 화면에서 채우고 완성된 프롬프트를 복사
- **히스토리** — 저장할 때마다 전체 스냅샷이 남고, 어떤 항목이 바뀌었는지 표시. 되돌리기도 지우지 않고 새 버전으로 쌓임
- **MD 파일로 올리기·내려받기** — 문서 화면의 "MD로 내려받기", 작성·수정 폼의 "MD 파일에서 불러오기". 형식은 아래 "MD 파일 형식" 참고
- 복사 횟수 기반 인기 순위 (이 위키에서 가장 정직한 지표)
- 다크 모드 (시스템 설정을 따라가되 사이드바에서 덮어쓰기 가능)

### 마이페이지 (누구나, `/me`)

관리자를 거치지 않고 스스로 할 수 있는 일들을 모아 뒀다. 사이드바 아래 이름을 누르면 열린다.

- 이름·소속·직급·직함 수정 (**이메일은 로그인 식별자라 관리자만 바꾼다**)
- 비밀번호 변경 — 지금 비밀번호를 확인하고, 바꾸면 **다른 기기는 모두 로그아웃되고 지금 창은 남는다**
- 로그인 중인 기기 목록 — 모르는 기기를 골라 내보내거나 한 번에 정리
- 내가 쓴 문서 / 내가 손댄 문서

### 백오피스 (관리자만)

- **현황** — 구성원·문서·세션 숫자, 많이 고친 사람, 3개월 넘게 손대지 않은 문서, 최근 관리 활동
- **구성원** — 추가(비밀번호 자동 발급)·정보 수정·권한 변경·계정 중지/재개·비밀번호 재설정
  - **직급**(팀장·매니저 — 조직 안에서의 자리)과 **직함**(모바일 엔지니어 — 하는 일)은 따로 둔다. 직급은 자주 쓰는 값을 골라 넣을 수 있고 직접 적어도 된다
- **문서** — 초안·보관까지 전부 조회, 상태 변경, 완전 삭제(히스토리까지)
- **카테고리** · **도메인** — 트리로 보면서 추가·하위 추가·상위 옮기기·순서 변경·삭제
- **태그** — 이름 변경·병합·삭제, 아무도 안 쓰는 태그 골라내기
- **활동 기록** — 구성원이 한 일까지 전부 남는다
  - **구성원별 현황**: 기간(24시간·7일·30일) 안에 누가 로그인·작성·수정·복사·내려받기를 몇 번 했는지, 마지막 활동은 언제인지. 아무것도 안 한 사람도 빠뜨리지 않는다
  - **기록**: 사람·갈래(로그인/문서/사용/계정/관리)·종류로 거른다. 현황 표에서 사람을 누르면 그 사람 기록만 보인다
  - **로그인 실패**도 남는다. 없는 이메일로 두드린 것까지 — 누가 남의 계정을 두드리는지 알 수 있다
  - 대시보드의 "최근 관리 활동" 에는 관리 갈래만 보인다 (복사 기록에 묻히지 않게)

## 사이드바 탐색기

왼쪽 사이드바는 VSCode 탐색기처럼 움직인다. 팀이 폴더, 문서가 파일이다.

### 할 수 있는 것

- **폴더 만들기** — 팀 폴더에 마우스를 올리면 나오는 폴더 아이콘. 이름을 적고 Enter. **관리자가 아니어도 누구나** 자기 팀 아래에 만들 수 있다
- **문서 옮기기** — 문서를 폴더 위로 끌어다 놓는다. 폴더 위에 잠깐 물고 있으면 저절로 펼쳐진다
- **MD 파일 넣기** — 폴더의 ↑ 아이콘으로 고르거나, 바탕화면에서 폴더 줄 위로 바로 끌어다 놓는다. 여러 개를 한 번에 넣을 수 있다
  - 그대로 저장해도 되는 파일은 **바로 저장**하고, 제목을 못 찾았거나 모르는 도메인이 적혀 있는 등 걸리는 게 있으면 저장하지 않고 작성 화면을 열어 확인받는다
- **새 문서** — 폴더의 파일 아이콘. 그 폴더가 미리 골라진 채로 작성 화면이 열린다
- 키보드: `↑` `↓` 이동, `→` 펼치기·안으로, `←` 접기·상위로, `Enter` 열기(폴더는 그 팀 목록), `Space` 접고 펴기
- 폴더 이름 바꾸기·옮기기·삭제와 **맨 위 팀 폴더 만들기는 백오피스(관리자)** 에서 한다
- 끌어다 놓기는 마우스가 있는 화면에서만 된다. 휴대폰에서는 문서 수정 화면에서 카테고리를 바꾸면 된다

## 알아 둘 것

### SPA 로 둔 이유

검색 노출을 노리는 화면이 아니라 SEO 도 첫 페인트 경쟁도 없다.
SSR 을 끄면 브라우저에 저장한 토큰을 서버 렌더링과 맞출 일이 사라진다.
필요해지면 `nuxt.config.ts` 의 `ssr: false` 를 지우고 인증 관련 UI 를 `<ClientOnly>` 로 감싸면 된다.

### 사이드바는 문서를 통째로 받아 둔다

`useWikiNav` 가 `per_page=200` 으로 한 번에 받아 트리를 그린다.
수백 건까지는 접었다 펴는 맛이 좋아서 이렇게 뒀고,
수천 건이 되면 카테고리별로 나눠 부르도록 바꾸면 된다.

### 토큰은 localStorage 에 둔다

로그인하면 받은 토큰을 localStorage 에 넣고 `Authorization: Bearer …` 로 보낸다.
XSS 에 약하다는 걸 알고 내린 선택이다 — 프론트(3000)와 API(3001)의 오리진이 달라서
쿠키를 그대로 태우기 어려웠다. 같은 도메인으로 합치면 HttpOnly 쿠키가 낫다.
바꿀 곳은 `app/composables/useAuth.ts` 다.

## 배포

```bash
bin/deploy      # 로컬에서 빌드 → 정적 파일만 업로드
```

**빌드는 반드시 로컬에서 한다.** 서버 램이 1GB 뿐이라 거기서 Nuxt 를 빌드하면 메모리 부족으로 죽는다.
`nuxt generate` 결과가 순수 정적 파일이고 nginx 가 그대로 내준다.

배포 대상은 저장소에 적어 두지 않는다. 맨 위에 `.deploy.env` 를 만들어 두면 알아서 읽는다
(`.gitignore` 에 들어 있다).

```bash
PRISM_HOST=ubuntu@203.0.113.10
PRISM_KEY=~/keys/prism.pem
PRISM_DOMAIN=prism.example.com
```

**nginx 의 `try_files` 순서가 중요하다.**
`try_files $uri ...` 를 먼저 두면 `/login` 이 디렉터리와 맞아떨어져 `/login/` 으로 301 이 난다.
그러면 SPA 라우터가 보는 경로와 주소창이 어긋나 로그인이 자기 자신으로 돌아가는 순환에 빠진다.
`try_files $uri.html $uri/index.html $uri /index.html;` 순서로 파일을 먼저 찾게 해 둬야 한다.

## 만들면서 걸렸던 것

나중에 같은 데서 막히지 않도록 남겨 둔다.

**Vue 템플릿에 중괄호 두 개를 그대로 못 쓴다.**
`{{ '{{변수명}}' }}` 처럼 안내 문구로 쓰려다 파서가 깨졌다 (`Unterminated string constant`).
스크립트에 상수로 빼서 넘겨야 한다. 타입 검사로는 안 잡히고 화면이 통째로 안 뜬다.

**clearNuxtData 는 다시 읽어 주지 않는다.**
새 문서를 만들어도 사이드바 트리에 안 나타났다. 캐시를 비우기만 하면
이미 화면에 붙어 있는 컴포넌트는 스스로 다시 부르지 않는다.
비운 뒤 `refreshNuxtData` 까지 불러야 한다 (`usePromptCache.ts`).

**useAsyncData 는 키가 같으면 결과를 공유한다.**
상세와 수정 화면이 같은 키를 쓰다 보니, 저장하고 상세로 돌아가면 방금 고친 내용이 아니라
열기 전 내용이 보였다. 서버는 멀쩡한데 화면만 예전 것이었다.

**테스트 헬퍼 안의 `JSON` 은 `ActiveSupport::JSON` 이다.**
`ActiveSupport::TestCase` 안에서 `JSON.parse` 를 부르면 상수 탐색이 그쪽을 먼저 찾아
`undefined method 'parse'` 가 난다. `::JSON.parse` 로 못 박아야 한다.

**401 을 전부 "세션 만료" 로 보면 안 된다.**
마이페이지에서 지금 비밀번호를 틀리게 넣으면 서버가 401 을 주고,
프론트가 그걸 세션 만료로 읽어 **사용자를 로그아웃시켜 버렸다**. 오류 메시지는 보이지도 않았다.
서버는 422 로 바꾸고(로그인은 되어 있고 적어 넣은 값만 틀린 것이므로),
프론트는 `code: "unauthenticated"` 가 붙은 401 만 로그아웃으로 취급하게 했다.

**minitest 6 에는 `stub` 이 없다.**
`minitest/mock` 이 별도 gem 으로 빠졌다. 의존성을 늘리지 않으려고, 테스트 안에서
`define_singleton_method` 로 잠깐 덮어썼다가 `remove_method` 로 되돌린다 (`activity_tracking_test.rb`).

**json gem 3.x 는 위 "알아 둘 것" 참고.** 증상이 엉뚱한 데서 터진다 —
SQLite 를 쓰던 때는 `schema.rb` 덤프가 깨지는 것으로 보였다.
